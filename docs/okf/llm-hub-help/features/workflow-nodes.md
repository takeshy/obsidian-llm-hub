# Workflow Nodes

Workflow YAML is usually generated by AI, but users may ask what node to use or how nodes behave. Each node has an `id`, a `type`, type-specific properties, and usually `next` to continue execution.

# Node Categories

- Variables: `variable`, `set` declare and update variables.
- Control: `if`, `while` branch or loop. Conditional edges use `true` and `false` labels.
- LLM: `command` runs a prompt on any configured model and saves text or generated image output.
- Data: `http`, `json`, `script` call APIs, parse JSON, or run JavaScript.
- System: `shell` runs a local system command.
- Notes: `note`, `note-read`, `note-search`, `note-list`, `folder-list`, `open` operate on vault content.
- Files: `file-explorer`, `file-save` select or save binary/text files.
- Prompts: `prompt-file`, `prompt-selection`, `dialog` ask the user for file, selection, or dialog input.
- Composition: `workflow` runs another workflow as a sub-workflow.
- External: `mcp`, `obsidian-command` call MCP tools or Obsidian commands.
- Utility: `sleep` pauses execution.
- RAG: `rag-sync` runs a full incremental sync of a local RAG setting.

# Key Nodes

`command` supports `prompt`, optional `model`, `ragSetting` (`__websearch__`, `__none__`, or setting name), `vaultTools` (`all`, `noSearch`, `readOnly`, `none`), `mcpServers` (comma-separated names of MCP servers configured in plugin settings), `attachments`, `enableThinking`, `saveTo`, and `saveImageTo`. The model can be any verified API provider, a local LLM, or the Gemini/Codex CLI; Claude CLI is not supported in workflows.

`command` and `mcp` support `confirm` (default: "true"). Set `confirm: "false"` to skip MCP tool approval for that node, including automatic execution; otherwise server approval settings apply. `command` also supports `vaultTools: "readOnly"` to allow built-in Vault search and reading without file changes. External MCP and skill tools retain their own permissions. See [MCP Support](./mcp.md) for the approval dialog and server allowed lists.

`note` writes content with `path`, `content`, `mode` (`overwrite`, `append`, `create`), `confirm`, and `history`. Confirmation defaults to safe behavior.

`note-read` reads a file into `saveTo`; encrypted files trigger a password prompt and cache the password for the session.

`note-list` can filter by folder, recursion, tags, creation or modification window, sort field, sort order, and limit.

`note-search` searches file names or contents and returns matched context.

`folder-list` lists vault folders from a parent folder.

`open` opens a vault file in Obsidian.

`dialog` shows a modal dialog, can render Markdown, can collect text input, and can return selected buttons or options.

`prompt-file` asks the user to select a file; the picker lists Markdown and `.encrypted` files. In hotkey and event runs it can automatically use the active or event file.

`prompt-selection` asks for editor selection. In hotkey runs it uses the current selection or full active file content; in event runs it uses the event file content.

`file-explorer` selects any supported file and returns `FileExplorerData` with path, name, extension, MIME type, content type, and text or Base64 data.

`file-save` saves FileExplorerData or generated binary/text data back to the vault.

`workflow` executes another workflow as a sub-workflow and can pass variables.

`rag-sync` runs a full incremental Local RAG sync. `ragSetting` selects the setting and defaults to the currently selected setting. Target folders, exclusion patterns, and embedding configuration come from that setting. Gemini Embedding multimodal models use native image/PDF/audio/video input; Local/OpenAI-compatible embedding endpoints index Markdown and extracted PDF text. The legacy `path` property is accepted for compatibility but does not limit the sync to one file.

`http` sends external requests. Warn users that HTTP nodes can transmit vault data to third-party services.

`json` expects `source` to be a bare variable name, not `{{source}}` interpolation.

`script` runs JavaScript in the workflow sandbox.

`shell` runs a local system command with `command`, optional `args` (JSON array), `cwd`, `timeout`, `env`, `throwOnError`, `saveTo` (stdout), `saveStderrTo`, and `saveExitCodeTo`. Warn users that shell nodes execute arbitrary commands on the local system with the user's permissions.

`mcp` connects to an MCP server given directly by its `url` property and calls `tool` with optional `args` and `headers`. It does not use the MCP servers configured in plugin settings; those are used by the `command` node's `mcpServers` property.

`obsidian-command` runs an Obsidian command by command ID and is useful for operations such as encryption workflows.

`sleep` pauses execution for a configured duration.

# Obsidian Command Node

Use `obsidian-command` to run an Obsidian command by command ID from a workflow. It is useful when the workflow should call an existing plugin command instead of reimplementing that behavior.

Common use cases:

- Run LLM Hub encryption commands after selecting or generating files.
- Chain Obsidian-native commands into a larger workflow.
- Trigger commands exposed by other plugins when the command ID is known.

For bulk encryption workflows, combine file or folder selection with `obsidian-command` so users can approve the workflow and then let it run the command across selected targets. Keep confirmation enabled for workflows that can modify many files.

# Workflow Options

`options.showProgress: false` hides the execution progress modal for hotkey or workflow-list execution. The visual workflow panel always shows progress.

# Skill Workflow Outputs

When invoked from chat through `run_skill_workflow`, every variable whose name does not start with `__` (double underscore) is returned to the chat model; single-underscore system variables such as `_date` or `_workflowName` are included. A final `command` node just to display output is unnecessary; put output presentation rules in `SKILL.md`.
